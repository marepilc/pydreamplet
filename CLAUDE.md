# pyDreamplet

Monorepo for the pyDreamplet library, its documentation site and showcase
examples.

## Layout

- `pydreamplet/` — the library (Python >= 3.12, published to PyPI)
- `tests/` — pytest suite for the library
- `docs/` — documentation site (Nuxt Content), deployed to https://py.dreamplet.com
- `docs/content/reference/` — API reference, one Markdown file per module
- `docs/public/showcase/` — gallery SVGs, generated by the showcase examples
- `showcase/` — example scripts (Python >= 3.14), using the local library

## Keep the docs in sync

Every change to the public API ships with its documentation in the same commit:

- Update the matching page in `docs/content/reference/` (signature list, section
  with description and a runnable example).
- Mark new functions, classes and parameters with
  `::version-badge{version="X.Y.Z"}` followed by `::`, using the upcoming
  release version from `pyproject.toml`.
- Update tutorials in `docs/content/` that use changed or removed APIs.
- Add a `CHANGELOG.md` entry.

## Checks

Library (from the repo root):

```shell
uv run pytest
uv run basedpyright
uv run mypy pydreamplet tests
uv run ruff check pydreamplet tests
```

Documentation (from `docs/`):

```shell
npm ci
npm run generate
```

Showcase (from `showcase/`):

```shell
uv run dp <example> -m light
uv run dp <example> -m dark
uv run ruff check .
```

## Deployment

Pushing changes under `docs/` to `master` deploys the documentation to the VPS
(`.github/workflows/deploy-docs.yml`). Library releases are published to PyPI
by pushing a `vX.Y.Z` tag matching the `pyproject.toml` version
(`.github/workflows/publish.yml`, Trusted Publishing).
